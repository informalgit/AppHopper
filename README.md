# AppHopper

**Windows 上的应用级 `Alt+Tab`，外观 UI 来自 PowerToys Window Hopper**

两个快捷键, 职责完全分开:

| 快捷键 | 在什么之间切换 | 行为 |
|---|---|---|
| `Alt+Tab` | **应用** | 每个应用只占一个条目，按最近使用排序；前台应用的兄弟窗口不出现，所以 `Alt+Tab` 永远落在*另一个*应用上 |
| ``Alt+` `` | **前台应用的窗口** | 交给 [PowerToys Window Hopper](https://learn.microsoft.com/zh-cn/windows/powertoys/window-hopper)(或任何应用内切换器)处理 |

再也不用在五个资源管理器窗口之间"路过"才能到达浏览器：`Alt+Tab` 直接跳到下一个*应用*，``Alt+` `` 在当前应用内部循环

## 1.1.2beta1

- 修复启动失败时吞掉 `Alt+Tab`：投递失败直接放行，候选不足等启动失败通过带专用标记的 `SendInput` 回退；匹配的 `Tab` 松开会被消费，物理 `Alt` 松开始终放行。

- 默认日志隐藏窗口标题和可执行文件名，`--log-verbose` 单独使用即可启用详细日志；按 UTF-8 字节限制完整记录，文件不超过 8 MiB。
- 移除 F24 授权按键注入及面向目标窗口的输入队列连接，最小化窗口异步还原；保留实际前台落定检查。
- 自启动检查安装路径、重解析点、文件及父目录 ACL；普通身份可修改的路径会被拒绝，失败时菜单不会假装启用成功。

这是测试版，未保证消除任务栏闪烁。回归测试覆盖输入、日志和自启动保护；隔离桌面的运行验证不能替代输入桌面上的快速切换、游戏及 UWP 实测。

## 1.1.2beta7

- **回归修复**：beta6 删除 `AllowSetForegroundWindow` 导致切换失败率从约 3% 升到约 28%。那个调用在这里每次都返回 ERROR_ACCESS_DENIED、按文档语义不授予任何权限，看起来是纯粹的浪费——但它**消耗的时延**正是让宿主的前台授权在移交前得以保持的原因。交替实测：删除后失败 8/20、7/20；恢复后 1/20、2/20、0/20。已恢复并在代码注释中写明其价值是时序而非权限，以及它与当初那个真正错误的自进程预检的区别。
- 同样确认移交前的有界 `WM_NULL` 屏障必须保留：移除后失败稳定在 6/20，保留则 1–4/20。
- beta6 的其余改动（消息链路异常兜底、越界索引检查、放弃会话归还前台、钩子安装日志、绘制资源异常安全、owner 链判定复用）均未发现回归，予以保留。
- 回归测试增至 19 项，新增移交路径的边界断言。


- 消息处理链路加异常兜底：`WndProc → HandleAppMsg → Commit` 原本全程没有 try/catch，枚举窗口、跨进程读标题或 COM 调用一旦抛异常就会穿出消息循环、带走整个进程。现在统一在 `HandleAppMsg` 捕获并安全结束会话；`EnumWindows` 回调同样加了兜底，因为回调内抛异常会跨越非托管帧。
- 鼠标点击传入的索引按不可信输入处理：`WM_APP_COMMITAT` 的参数此前直接写入 `_index`，紧接着 `Commit()` 就用它访问 `_apps[_index]`，越界即崩溃。现在先做范围检查，非法索引记日志并忽略。
- `AbortSession`（会话中所有窗口都消失）此前只隐藏浮层就结束，前台会停在已经隐藏的自家窗口上、键盘无处可去；现在与 `Cancel` 共用同一条前台归还路径。
- 启动时记录键盘钩子安装结果：钩子装不上时程序照常运行但完全不响应 Alt+Tab，此前从外部完全看不出原因。
- 每次枚举复用 owner 链判定结果，避免同一个根窗口被反复查询（DWM + 虚拟桌面 COM 调用）。面板升起耗时未受影响（p50 59ms → 61ms）。
- 卡片绘制与分层窗口提交拆分为独立方法，`GraphicsPath`、`StringFormat` 和内存 DC 在异常路径上也会释放；托盘图标的箭头端帽同理。
- 删除死代码：`AllowSetForegroundWindow`（授权目标进程却由本进程调用，对本次激活无作用）、`ShowWindow`、`GetClassLong`、`GetAncestor`、`FindWindowByClass`、未使用的 `oldIndex`。
- 回归测试从 14 项增至 18 项，新增越界索引、消息异常隔离、图标独立性与记忆化判定四项，均以变异测试验证（改坏实现即失败）。
- **刻意回退**：审查发现 `Icon.FromHandle` 不接管句柄、`Dispose` 不会销毁，图标会按可执行文件数量缓慢泄漏。修复它需要每取一次图标多做一次 `Clone()`，而图标加载在 Alt+Tab 启动路径上，实测会让切换失败率从 0/25 升到 10/25。句柄数量有界（每程序一个、进程退出即回收），为此牺牲切换可靠性不划算，故保留原样并在代码注释写明原因。

## 1.1.2beta5

- 修复“按住 Alt 不放、按 ESC 关闭切换条时任务栏闪烁”：`Cancel` 原先在 Alt 仍按住时就把前台交还源窗口。Alt+Tab 手势进行中途放弃前台所有权会被 Windows 记为一次前台变更，闪烁正是由此而来。现在改为**把交还推迟到 Alt 松开之后**，由看门狗（≤30ms）完成；若那时前台已被系统或用户自己交还，则不再干预。
- 领取前台时宿主改为停靠在源窗口所在位置，而不是原点，避免会话期间源尺寸的宿主窗口在左上角闪现。
- 输入桌面实测：连续 3 次“按住 Alt + ESC 取消”，闪烁 0 次，前台在 Alt 松开后 50–70ms 内自行归位。
- **未解决**：以提权控制台为切换目标时约 25% 的提交仍被 Windows 拒绝。已用对照实验排除宿主位置因素的干扰（保留上次位置与停靠源窗口两种配置拒绝率相同），失败集中在特定目标窗口上，与 ESC 修复无关。此项需要独立分析。

## 1.1.2beta4

- **根因修复：领取前台时宿主必须具有真实尺寸。** 此前宿主被设为 0×0 零尺寸窗口——它确实能成为 `GetForegroundWindow()`，但 Windows 拒绝让它把前台转交出去：会话内每一次 `SetForegroundWindow` 都被拒，而**拒绝正是任务栏闪烁的来源**。日志证据完全吻合：`activation foreground queue flags=0x0 focus=0x0`、`accepted=False`，而宿主 HWND 却是前台。现改为按源窗口尺寸显示（带 `SWP_NOZORDER`），真实面板几何在布局算完后照常应用。
- 提交时的激活不再因一次 `SetForegroundWindow` 被拒就放弃：宿主仍在前台时走输入队列移交作为最后手段，移交后不再重试（重试只会等量增加闪烁）。移交前做有界 `WM_NULL` 同步，避免把挂起窗口当作可激活目标。
- 最小化目标改为还原后再激活：`SW_RESTORE` 是异步的，窗口仍在最小化时激活会被拒（同样表现为闪烁且不上来）。现在有界等待其离开最小化状态（上限 250ms）再请求激活。
- 明确不使用 `BringWindowToTop`：它绕过前台锁，正是“任务栏闪烁但窗口不上来”的成因。
- 输入桌面实测（同一脚本、同一前台目标，各 25 次 Alt+Tab）：修复前成功 11 次、失败 19 次、闪烁 44 次；修复后 **25/25 成功、0 失败、闪烁 0 次**，`SetForegroundWindow` 被拒次数由 34 次降为 0。此结果不覆盖真实硬件输入、游戏或 UWP。

## 特性

- **真正的应用级 `Alt+Tab`** —— 窗口按进程分组,按 Z 序(最近使用)排序。每个组的代表窗口是其最近使用的窗口,因此切回某个应用时,你会回到上次离开的地方。
- **Window Hopper 风格 UI** —— 浮层完整移植自 PowerToys 的 `AltWindowCycle` 模块:WinUI 风格圆角卡片、每卡片图标+标题头、系统强调色双环选中框、跟随系统的深浅主题、带页码指示的分页,以及**不做背景变暗**。
- **DWM 实时缩略图** —— 与任务栏预览同机制的实时合成画面,按卡片比例居中裁剪,绝不拉伸变形。
- **完整的鼠标支持** —— 点击卡片直接切换、点击面板外任意位置取消、滚轮循环选择。(`Esc` 同样可以取消。)
- **虚拟桌面感知** —— 只列出*当前*桌面上的窗口(通过公开的 `IVirtualDesktopManager` 判断),切换永远不会把窗口拽到别的桌面。
- **低侵入** —— 不修改其他窗口的样式、归属或任务栏属性，只在切换时请求还原最小化目标；无法建立会话时，重放这次 `Tab` 交还给 Windows 原生切换器。
- **按显示器、DPI 感知** —— 面板显示在前台窗口所在显示器的中央,按该显示器 DPI 缩放,最多 6 列并自动分页。
- **单文件、零依赖** —— 一个 C# 源文件,用 Windows 自带的编译器即可构建。无需安装器、无需装运行库,绿色单 exe。


## 构建

1. **最简单的做法：双击仓库里的 `build.bat`**，它会先结束正在运行的实例，并嵌入 `app.manifest`，使生成的 exe 启动时自动申请管理员权限；若已有实例正以管理员权限运行，**请先从托盘退出**，否则输出文件被占用会导致编译失败。
2. 手动执行等价命令:
    ```bat
    C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe -nologo -target:winexe -platform:anycpu -optimize+ -win32manifest:app.manifest ^
      -r:System.dll -r:System.Core.dll -r:System.Drawing.dll -r:System.Windows.Forms.dll ^
      -out:AppHopper.exe AppHopper.cs
    ```
适用于 Windows 10 和 11。

## 使用

运行 `AppHopper.exe`——托盘出现图标(右键:*Enabled*、*Start with Windows*、*Exit*)。然后:

| 输入 | 动作 |
|---|---|
| `Alt+Tab` | 打开切换条,预选下一个应用 |
| 按住 `Alt`,连按 `Tab` / `Shift+Tab` | 向后 / 向前循环 |
| 松开 `Alt` | 切换到选中的应用(最小化的会还原) |
| `Esc` / 点击面板外 | 取消 |
| 点击某张卡片 | 立即切换到该应用 |
| 鼠标滚轮 | 循环选择 |

应用列表每次打开切换器时实时计算，没有任何需要配置的选项。诊断：以 `--log` 参数启动；日志最多 8 MiB，默认隐藏窗口标题和可执行文件名，仍保留 HWND、窗口类和时序。需要完整枚举细节时使用 `--log-verbose`，分享详细日志前请检查敏感内容。日志中的 `hotkey: alt+tab -> start`、`start aborted:` 和 `alt+tab fallback:` 用于区分消息到达、启动失败和主动回退；没有记录本身不能证明钩子未到达，日志也可能已满或不可写。

运行 `AppHopper.exe --self-test` 执行全部回归，双击 `self-test.bat` 只是把它编译到临时目录再跑一遍。测试代码已并入 `AppHopper.cs`，没有独立的测试工程：覆盖布局/分页/裁剪、单显示器居中、逐窗口日志脱敏与 UTF-8 上限、日志流失败后的行为、自启动路径与 ACL、原生回放不污染物理按键、键盘钩子的放行/吞键/自动重复/replay 标记，以及无前台所有权时拒绝激活。自检在单实例互斥量之前运行，可与正在运行的切换器并存，不安装钩子、不改变前台、不写自启动注册表，退出码 0 表示通过。

`Start with Windows` 仅允许安装在 `Program Files` 或 `Program Files (x86)` 下的受保护路径；名称符合但 ACL 可被普通身份修改、存在重解析点的路径同样会被拒绝。HKCU Run 注册不绕过 UAC，Windows 可能阻止管理员程序在登录时启动，不能保证无人值守自启。

## 实现原理(简版)

- 键盘钩子仅在消息投递成功后消费 `Alt+Tab`，并消费匹配的 `Tab` 松开；启动失败通过带标记的输入回放交还原生切换器，物理 `Alt` 松开不被拦截。
- 顶层窗口按 Z 序枚举,经经典 Alt-Tab 资格规则 + 当前桌面检查过滤,再按进程映像路径分组(UWP 窗口通过其子 `Windows.UI.Core.CoreWindow` 归因到真实应用)。
- 实时预览是 `DwmRegisterThumbnail` 合成画面,渲染进一块不透明圆角面板;卡片层(标题、描边、选中环、页码)用 GDI+ 画进预乘 alpha 的 DIB,再经 `UpdateLayeredWindow` 合成——与其移植来源的 PowerToys 模块相同的双层设计。
- 激活以本程序前台宿主为交接点，不注入授权按键。只有领取自身前台时才短时连接当前前台线程，目标激活前已经断开；最小化目标经 `ShowWindowAsync` 异步还原。跨队列激活通过带超时的 `WM_NULL` 等待处理，再检查实际前台；参考[微软的异步激活说明](https://devblogs.microsoft.com/oldnewthing/20161118-00/?p=94745/)。50ms 响应检查和 200ms/300ms 同步、落定预算不是所有 Win32 调用的硬超时；检查后前台线程突然挂起仍存在队列连接竞态，也不能越过 Windows 前台权限限制。
